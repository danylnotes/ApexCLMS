# Hosting

## Static demo on GitHub Pages

GitHub Pages serves static files only. It cannot run the platform's server, sign-in or PostgreSQL database, so the Pages site is a **read-only snapshot**: every page each fictional persona can reach, captured from a running instance. Forms show a notice instead of saving.

- Generated by `scripts/build-static-demo.mjs` into `pages-demo/` (committed).
- Published by `.github/workflows/pages.yml` on push.
- One-time setup: **Settings → Pages → Build and deployment → Source: GitHub Actions**. The default `github-pages` environment only allows deployments from the default branch; either merge to the default branch or add this branch under **Settings → Environments → github-pages → Deployment branches**.
- The site is served at `https://danylnotes.github.io/ApexCLMS/`.

Regenerate after changes:

```bash
cd ApexCLMS
npm run db:seed && npm run build && npm start -- -p 3200 &
node scripts/build-static-demo.mjs --base http://localhost:3200 --out pages-demo
```

## Full application

Any Node.js host with PostgreSQL works. Two tested-by-design options:

### Render (Blueprint)
`render.yaml` provisions a web service, a PostgreSQL database and a persistent disk for private files. In Render choose **New → Blueprint**, select the repository, then set `APP_URL` to the service URL. Migrations run as the pre-deploy step. Add a Render Cron Job calling `POST /api/v1/jobs/run` hourly with `Authorization: Bearer $JOBS_SECRET`.

To load the fictional demo data into an isolated demo service only: open a Render shell and run `ALLOW_DEMO_SEED=true npx tsx prisma/seed.ts`, and set `DEMO_MODE=true`.

### Docker (any container host)
Build the `Dockerfile`, provide `DATABASE_URL` (e.g. Neon, Azure Database for PostgreSQL, RDS), mount a persistent volume at `/data/storage`, run `npx prisma migrate deploy` as a release step and expose port 3000.

Note: serverless platforms with read-only file systems (e.g. Vercel) need the object-storage driver described in `DEPLOYMENT.md` before uploads will persist.
