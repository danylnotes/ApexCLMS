# Languages (English, Arabic, French)

The interface is available in English (source), Arabic (right-to-left) and French. Users choose a language with the language buttons on the sign-in page or the language menu in the app header; the choice is stored in the `apex_lang` cookie (one year). Without a cookie the browser's `Accept-Language` decides, falling back to English.

Records themselves — course titles and content, people's names, organisation data, free-text notes and stored notifications — are data and appear as entered.

## How it works

- `src/i18n/config.ts` — locales, labels, text direction, Intl locale (Arabic uses Latin digits so codes and figures read consistently).
- `src/i18n/translate.ts` — `translate(dict, locale, key, vars)`. **The key is the exact English text.** Missing translations fall back to English.
- `src/i18n/server.ts` — `getI18n()` for server components, server actions and route handlers.
- `src/i18n/active.ts` — `tr()` for synchronous server code (formatters, status labels, domain text). It uses the language resolved by the root layout for the current render; outside a render (tests, scripts, server actions) it is English.
- `src/i18n/client.tsx` — `useI18n()` for client components.
- `src/i18n/locales/{fr,ar}/<area>.ts` — translations. Strings used by **client components** must go in the `client-<area>.ts` file (only those are sent to the browser); everything else in `<area>.ts`.
- `/lang?set=ar&next=/path` — switches language (works without JavaScript).
- `<html lang dir>` is set from the locale. Layout uses logical Tailwind utilities (`ps-`, `pe-`, `ms-`, `me-`, `start-`, `end-`, `text-start`, `text-end`, `border-s`, `border-e`) so it mirrors in Arabic. Directional icons (chevrons, arrows) get `rtl:-scale-x-100`.

## Writing translatable code

Server component:

```tsx
import { getI18n } from "@/i18n/server";

export async function generateMetadata() {
  const { t } = await getI18n();
  return { title: t("Course Catalogue") };
}

export default async function Page() {
  const { t } = await getI18n();
  return <PageHeader title={t("Course Catalogue")} description={t("{count, plural, one {# course} other {# courses}}", { count })} />;
}
```

Synchronous server helpers or non-async server components: `import { tr } from "@/i18n/active"` and call `tr("…")`.

Client component (`"use client"`): `const { t } = useI18n();` and put the strings in `locales/{fr,ar}/client-<area>.ts`.

Rules:

1. Wrap every user-visible English literal: headings, labels, buttons, placeholders, `aria-label`, `title`, table headers, empty states, notices, confirmation prompts, metadata titles.
2. Interpolate with placeholders — never concatenate translated fragments: `t("Due {date}", { date: fmtDate(d) })`, not `"Due " + …`.
3. Plurals use the ICU subset: `{count, plural, one {# day} other {# days}}`. Arabic translations may use `zero`, `one`, `two`, `few`, `many`, `other`.
4. Do not translate data: names, course titles, codes, enum values used in logic, URLs, CSS classes, test IDs.
5. Dates and numbers: use `fmtDate`, `fmtDateTime`, `fmtRelative`, `fmtHours`, `fmtMinutes` from `@/lib/format`; for custom formats use `activeIntl()` from `@/i18n/active` instead of a hard-coded `"en-GB"`.
6. Status maps in `@/lib/status` already translate on read.
7. Add every new key to **both** `fr` and `ar` files with natural, professional translations (Arabic: Modern Standard Arabic suitable for an energy company; French: standard business French). Keep placeholders (`{name}`, `#`) unchanged. `tests/unit/i18n.test.ts` fails if any `t("…")` / `tr("…")` literal is missing from a dictionary.
8. In translations, arrows that indicate "next" (→) become ← in Arabic.
